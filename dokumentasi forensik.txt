    fun pasteText(text: String) {
        if (text.isEmpty()) return
        // Normalisasikan CRLF (\r\n) dan standalone CR (\r) menjadi Unix newline (\n) tanpa mengubah karakter lain
        val normalized = text.replace("\r\n", "\n").replace('\r', '\n')

        // Jika DECSET 2004 (Bracketed Paste Mode) aktif di terminal (misal di bash, zsh, nano, vim),
        // bungkus dengan escape sequence \u001B[200~ dan \u001B[201~.
        if (buffer.isBracketedPasteMode) {
            sendText("\u001B[200~$normalized\u001B[201~")
        } else {
            sendText(normalized)
        }
    }

    fun sendText(text: String) {
        if (!isRunning || outputStream == null) {
            AppLogger.w("NativeTerminal", "Sesi [$name] mati/terputus. Meluncurkan ulang sesi...")
            initializeProcess()
        }
        sessionScope.launch(Dispatchers.IO) {
            val out = outputStream ?: return@launch
            try {
                val bytes = text.toByteArray(Charsets.UTF_8)
                out.write(bytes)
                out.flush()
            } catch (e: Exception) {
                AppLogger.e("NativeTerminal", "Gagal kirim teks ke [$name]: ${e.message}")
            }
        }
    }

Analisis:
- sendText() mengirim byte UTF-8 murni langsung ke stdin proses Linux / PTY master.
- Tidak ada filter, modifikasi, pencegatan, atau masking di level data stream.
- Terminal DevBox mengadopsi prinsip zero local-echo (hanya menggambar apa yang dikembalikan dari stream output PTY).
- Ketika Antigravity CLI meminta token, CLI menonaktifkan echo pada termios driver TTY. Driver TTY kernel tidak memantulkan input, sehingga layar tetap kosong. Ini adalah standar keamanan Unix.

IV. ANALISIS MENDALAM AKAR MASALAH PER KASUS
================================================================================

--------------------------------------------------------------------------------
KASUS A: POLA OUTPUT "CHARLIEALPHA$" DAN "BRAVO$" PADA cat -A
--------------------------------------------------------------------------------
1. GEJALA:
Pengguna menjalankan:
   cat -A
Kemudian menempelkan 3 baris:
   ALPHA
   BRAVO
   CHARLIE
Output terminal terlihat:
   ALPHA
   BRAVO
   CHARLIEALPHA$
   BRAVO$

2. AKAR MASALAH TERVERIFIKASI:
Pola tersebut BUKAN karena DevBox mengirim input dua kali, bukan karena callback paste terpanggil dua kali, dan bukan kesalahan Canvas.

Pola tersebut terjadi karena interaksi 3 faktor:
A. Teks paste yang disalin dari clipboard tidak memiliki karakter newline penutup setelah kata "CHARLIE" (payload: "ALPHA\nBRAVO\nCHARLIE").
B. Program `cat -A` berjalan dalam mode kanonikal standar Linux dengan driver TTY echo aktif.
C. Terjadi perbedaan waktu pembacaan antara echo TTY (instan saat byte masuk) dan output dari program `cat -A` (setelah line buffer \n diproses).

Kronologi Kejadian per Karakter:
1. DevBox mengirim string "ALPHA\nBRAVO\nCHARLIE" ke stream master PTY.
2. Kernel TTY menerima "ALPHA\n":
   - TTY line discipline langsung meng-echo "ALPHA\r\n" ke terminal reader.
   - Karena ada karakter '\n', kernel membuka blokir pembacaan baris 1 untuk program `cat`.
3. Kernel TTY menerima "BRAVO\n":
   - TTY line discipline meng-echo "BRAVO\r\n" ke terminal reader.
   - Karena ada karakter '\n', kernel membuka blokir pembacaan baris 2 untuk program `cat`.
4. Kernel TTY menerima "CHARLIE":
   - TTY line discipline meng-echo "CHARLIE" ke terminal reader.
   - Kursor terminal DevBox kini berada di Baris ke-3 Kolom ke-7 (tepat setelah huruf 'E' pada CHARLIE).
   - Karena TIDAK ADA karakter '\n', kernel TTY TIDAK membuka blokir baris 3 untuk `cat`. Kata "CHARLIE" tertahan di antrean kanonikal TTY.
5. Sementara itu, program `cat -A` yang telah membaca Baris 1 ("ALPHA\n") mulai mencetak outputnya:
   - Sesuai fungsi `cat -A`, ia mencetak string dengan penanda akhir baris '$': "ALPHA$\r\n".
   - Output ini tiba di terminal DevBox saat kursor masih berada di Baris 3 Kolom 7!
   - Akibatnya, "ALPHA$" langsung digambar menyambung di baris yang sama, menghasilkan:
     "CHARLIEALPHA$"
6. Karakter "\r\n" dari output `cat -A` baris 1 memindahkan kursor ke awal Baris ke-4.
7. Program `cat -A` kemudian mencetak output Baris 2 ("BRAVO\n"):
   - Output yang dicetak adalah "BRAVO$\r\n".
   - Dicetak pada Baris ke-4, menghasilkan:
     "BRAVO$"
8. Baris ke-5 kini menunggu pengguna menekan Enter (untuk menyelesaikan kata CHARLIE) atau Ctrl+C.

3. KESIMPULAN KASUS A:
- DevBox mengirim data tepat satu kali.
- Tulisan "ALPHA" dan "BRAVO" di baris 1 dan 2 adalah ECHO TTY.
- Tulisan "ALPHA$" dan "BRAVO$" di baris 3 dan 4 adalah OUTPUT PROGRAM `cat -A`.
- Penggabungan "CHARLIEALPHA$" terjadi murni karena "CHARLIE" tidak memiliki \n penutup sehingga kursor tidak berpindah baris sebelum program `cat` mencetak outputnya.

KASUS B: TOKEN ANTIGRAVITY CLI TIDAK TERLIHAT
--------------------------------------------------------------------------------
1. GEJALA:
Saat pengguna menempelkan token autentikasi ke Antigravity CLI, karakter token tidak tampak sama sekali di terminal.

2. AKAR MASALAH TERVERIFIKASI:
- Perilaku Normal Prompt Rahasia Unix:
  CLI Antigravity (seperti utilitas Unix aman lainnya: sudo, gh auth, passwd) memanggil konfigurasi termios untuk menonaktifkan echo terminal (`stty -echo` atau `c_lflag &= ~ECHO`) saat meminta token atau password.
- DevBox Arsitektur Murni (Zero Local Echo):
  Terminal DevBox tidak membuat echo tiruan di aplikasi Android. Tampilan layar 100% dikendalikan oleh output yang dikembalikan oleh kernel Linux PTY.
- Keberadaan Token di Stream Data:
  Fungsi `sendText()` di TerminalSessionManager.kt mengirimkan byte UTF-8 token secara utuh ke master PTY. Byte tersebut telah diterima oleh kernel Linux dan tersimpan di buffer pembacaan CLI.
- Begitu pengguna menekan tombol ENTER (\r), CLI Antigravity langsung membaca token tersebut dari stdin, memproses autentikasi, dan mengembalikan echo terminal ke kondisi normal.
- Kesimpulan: Ini BUKAN bug aplikasi DevBox. Token tidak hilang, token terkirim sempurna. Menyembunyikan token adalah standar keamanan Unix untuk mencegah kredensial terbaca oleh orang lain atau terekam screenshot.

KASUS C: TUI RESIZE TIDAK RESPONSIF & PREFERENSI TAMPILAN
--------------------------------------------------------------------------------
1. GEJALA:
Antigravity TUI tidak menyesuaikan ukuran saat rotasi atau perubahan viewport, dan preferensi ukuran terminal dianggap tidak tersimpan setelah aplikasi ditutup-buka.

2. AKAR MASALAH TERVERIFIKASI:
Ada 2 akar masalah yang terpisah:

A. Cacat Skrip Resize PTY di TerminalSessionManager.kt (Baris 320-330):
   ```bash
   for p in /proc/[0-9]*; do
     if [ "$(readlink $p/root 2>/dev/null)" = '$targetRootfs' ]; then
       if grep -z '^DEVBOX_SESSION_ID=$sessionId' "$p/environ" 2>/dev/null >/dev/null; then
         for fd in $p/fd/*; do
           target=$(readlink $fd 2>/dev/null);
           if [[ $target == /dev/pts/* ]]; then
             chroot '$targetRootfs' /usr/bin/stty -F "$target" rows $rows cols $cols 2>/dev/null;
           fi
         done
         break   <=== SUMBER KEGAGALAN
       fi
     fi
   done
   ```
   - Skrip di atas bermaksud mencari file descriptor PTS milik sesi aktif, lalu mengeksekusi `stty rows R cols C`.
   - Namun peletakan perintah `break` berada di luar loop FD dan di dalam blok PID pertama yang cocok dengan DEVBOX_SESSION_ID.
   - Sesi terminal dijalankan melalui `su -c ... exec /bin/bash -c '... /usr/bin/script ...'`.
   - Proses pertama yang tercatat di `/proc` dengan DEVBOX_SESSION_ID adalah proses wrapper pembungkus shell tersebut. File descriptor milik proses wrapper ini adalah anonim *pipe*, BUKAN `/dev/pts/*`.
   - Ketika loop memeriksa proses wrapper ini:
     1. Loop `for fd` tidak menemukan `/dev/pts/*`.
     2. Perintah `break` langsung mengakhiri pencarian PID di `/proc`!
     3. Proses anak sesungguhnya (`/bin/bash -l` dan `antigravity`) yang memegang `/dev/pts/*` tidak pernah diperiksa sama sekali!
   - Dampak Fatal: Perintah `stty` TIDAK PERNAH DIJALANKAN. Kernel Linux PTY tetap berukuran 80x30 selamanya. Sinyal SIGWINCH tidak pernah dibangkitkan.

B. Status Persistensi Preferensi:
   - Preferensi `terminal_font_size` sebenarnya disimpan di SharedPreferences ("devbox_terminal_prefs") dan dipulihkan saat startup.
   - Namun, sesi baru PTY selalu di-spawn dengan ukuran statis `stty rows 30 cols 80` (baris 119).
   - Karena cacat skrip resize di atas, saat TerminalCanvas selesai mengukur layar perangkat dan memanggil `updateWindowSize()`, panggilan tersebut gagal total di kernel.
   - Akibatnya, setiap kali aplikasi dibuka kembali, terminal selalu terkunci pada 80x30, menciptakan kesan bagi pengguna bahwa pengaturan ukuran terminal tidak tersimpan.

KASUS D: INPUT MASKING MENYISIPKAN "*****" KE PASTE DI SEMUA CLI
--------------------------------------------------------------------------------
1. GEJALA:
Menempelkan teks biasa (seperti "sahal arbani") pada CLI kadang menghasilkan awalan bintang yang tidak ada di clipboard: "*****sahal arbani".

2. AKAR MASALAH TERVERIFIKASI:
- Asal Kode:
  Pada commit 3f12641a (v1.0.36), pengembang mencoba memuaskan permintaan visual pengguna untuk prompt rahasia dengan membuat fungsi `displayMaskedInput()` di TerminalGridBuffer.kt.
- Mekanisme Cacat:
  Fungsi tersebut menulis karakter '*' langsung ke sel array `activeGrid[cursorRow][cursorCol]` dan menggeser nilai `cursorCol`.
  Karakter bintang ini TIDAK PERNAH dikirim ke stream PTY.
  Namun, sel array tersebut menetap di memori buffer terminal DevBox.
- Terjadinya Awalan "*****":
  Jika sebuah prompt sebelumnya meminta 5 karakter rahasia (atau pengguna pernah menempelkan 5 karakter), 5 sel pertama diisi '*'. Jika prompt tersebut berganti atau dibatalkan tanpa ada ANSI sequence untuk membersihkan baris (misal \u001B[2K), sel bintang tersebut tetap berada di layar.
  Ketika pengguna berikutnya menempelkan teks "sahal arbani", echo dari PTY dimulai setelah posisi kolom bintang tersebut.
  Di layar, tampak gabungan: "*****sahal arbani".
- Status Saat Ini:
  Pemanggilan `displayMaskedInput()` telah DIHAPUS dari `pasteText()` pada commit f7a858a4 (v1.0.47).
  Pada versi master saat ini (v1.0.70), fungsi tersebut sudah menjadi *dead code* (tidak dipanggil di mana pun).
  Pengguna yang masih melihat gejala ini menjalankan APK lama (v1.0.36–v1.0.46) atau menggunakan sesi lama yang belum di-reset.

   ```bash
   for p in /proc/[0-9]*; do
     if [ "$(readlink $p/root 2>/dev/null)" = '$targetRootfs' ] && grep -q -z '^DEVBOX_SESSION_ID=$sessionId' "$p/environ" 2>/dev/null; then
   ```
